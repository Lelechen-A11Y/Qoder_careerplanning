# PathMap MVP 技术栈与上线边界

## 当前技术栈

| 层 | 采用方案 | 当前用途 |
| --- | --- | --- |
| 语言 | TypeScript 5.7，strict | 画像、职业、路径、体验、复盘与服务意向类型 |
| UI | React 19 | 页面与交互组件 |
| 构建 | Vite 6、`@vitejs/plugin-react` | 本地开发和生产静态构建 |
| 路由 | React Router 7 | 首页、问卷、知彼、路径、复盘、护航六个路由 |
| 样式 | Tailwind CSS 3 + 少量 CSS | 响应式布局、暗色引导、对比条、时间轴、打印样式 |
| 动效 | Framer Motion | 故事切换、逐步问卷、卡片与结果转场；尊重减少动态偏好 |
| 图标 | Lucide React | 导航、任务、状态和行动按钮图标 |
| 条件样式 | clsx | 底线冲突、可行路径、选中和禁用状态 |
| 跨页状态 | React Context + `useState` | 画像、候选、计划、微体验、复盘和本地服务意向 |
| 本地留存 | 封装的 `localStorage` | 仅当前浏览器的数据留存，不提供账号、云同步或恢复 |
| 图形与分析 | Tailwind/CSS + 本地规则纯函数 | 薪资区间、风险对比、偏好排序、硬底线校验；不引入重型图表库 |
| 测试/质量 | Vitest + `tsc -b` + Vite production build | Agent 意图、召回和护栏规则单测；严格类型检查与生产构建 |

## 智能体当前实现

当前职业助手是**本地检索式 Agent 演示**，不调用模型、不连接网络。`src/agent/careerAgent.ts` 将流程拆为意图分类、职业/意图过滤、关键词召回、护栏检查、结构化输出；回答带演示资料名、更新时间和适用范围。薪资、市场趋势和学历门槛资料不足时会明确限制推断并建议人工核验；具体院校推荐、适配度裁决和就业/收入保证直接转人工。最近 5 轮以浏览器本地存储保存，并可结合画像底线做风险提醒。

流式视觉通过异步分段展示本地检索结果，不是 SSE 或模型 token 流。Agent 对话按需懒加载。`src/data/agentKnowledge.ts` 里的资料全部标注为 PathMap 演示样本，不能作为市场事实引用。核心规则有 Vitest 单元测试。

未来升级时可保持 `AgentResponse` / `AgentMessage` 的界面契约：Next.js Route Handler 或 BFF 负责鉴权、限流和 SSE，再转发 FastAPI；Python 服务用 LangGraph 承载分类、检索、相关性评估、生成、护栏和人工升级节点。只有导入并审核过来源的资料才进入 pgvector/Qdrant。Redis 会话与 PostgreSQL 用户记忆应在获得用户同意后启用；LLM 密钥只保存在服务端。现有 React 对话窗口可把本地 `runCareerAgent` 适配器替换成远端流式适配器。

## 产品链路

1. **知己**：15–20 秒自动播放的分镜式故事入口；四个决策场景；必填阶段、专业、决策节点；选填选科、优势、成绩区间、学校背景、试错预算和每周时间；偏好探索与最后一题硬底线多选。
2. **知彼**：任务级职业卡片；真实日常、能力消耗、薪资范围、AI 风险、需求样本说明、退出成本和可逆窗口；硬底线过滤，偏好透明排序；最多两个职业 PK；预设模拟专家语料；15–20 分钟任务体验和体验证据记录。
3. **知行**：现实条件驱动的保底出口、交叉路径和 30 天测试；底线冲突标红且不进入推荐；成本、周投入、退出条件、复盘节点、打印摘要。
4. **护航**：站内节点提示、计划打卡、复盘资产、本人偏好说明卡、家长沟通摘要、真人服务/校准官/HR 工具的本地意向登记。

## 演示数据的解释边界

职业薪资、需求趋势和 AI 风险均为演示用假设值，不是市场统计或预测。本地检索助手不是实时 AI，知识条目和过来人语料也不是外部调研或真实访谈。它们在 UI 中有对应说明，正式上线前需由行业调研替换并带上来源、地区、时间和样本口径。

## 纯前端 MVP 的能力边界

当前可以完整演示单设备的调查、筛选、比较、体验、存档和复盘。`localStorage` 可被清理、不能跨设备同步，也不能保证适用于共享电脑上的隐私场景。站内日期提醒只会在打开网页时显示。

以下功能正式上线需服务端能力：账号与云端资产同步、可靠的浏览器/邮件/短信提醒、实时大模型问答及语料审核、真人服务预约/支付/客服、校准官身份与内容审核、HR 多租户画像工具和组织权限管理。若接入 AI，应由服务端持有密钥、过滤敏感信息、限制幻觉和输出范围；前端不得存 API Key。当前仍是既定的 Vite 纯前端项目，尚未迁移 Next.js 或创建 Python 服务。

## 生产化建议

- 后端 API：先使用轻量 REST（如 Fastify/NestJS）和 PostgreSQL；按需才加队列与缓存。
- 身份与访问：成熟 OIDC 服务；学生、家长、顾问、HR 的显式授权和租户隔离。
- 内容治理：职业资料带地区、年份、来源和审核状态；AI 回答限定在经审核资料库并返回来源。
- 安全与隐私：数据最小化、导出/删除、传输与静态加密、留存策略、错误监控；明确告知不做心理诊断或升学/就业保证。
- 质量：为底线规则、日期边界、退出规则和存储迁移加单元测试；增加 Playwright 主流程、键盘可访问性、移动/桌面视觉回归和真实设备检查。
- 发布：静态前端托管 + CI 类型检查/构建/端到端测试；按环境配置 API 地址，增加隐私政策、服务条款和数据使用说明。
